# Frontend integration

The Next.js app (`gs-hrms`) currently keeps all data in mock stores (`lib/*Store.ts`, `context/*Context.tsx`,
localStorage). It moves to this API **one module at a time**.

## Same origin

- **Azure**: Front Door serves both apps on `https://hrms.gs-it.ae`; `/api/*` goes to this backend.
- **Local**: the Next.js dev server proxies `/api` to `http://localhost:3001` so the browser also sees one origin.
  In `next.config.ts`:

  ```ts
  async rewrites() {
    return [{ source: '/api/:path*', destination: 'http://localhost:3001/api/:path*' }];
  }
  ```

The session is an httpOnly cookie. The frontend never reads or stores tokens and must remove the
`gsit.auth` localStorage session.

## Typed client from OpenAPI

`docs/api/openapi.json` is the contract (regenerated by `npm run openapi:export`, checked in CI).
Generate the frontend client from it rather than writing types by hand, e.g. with
`openapi-typescript` + `openapi-fetch`, or `orval` with TanStack Query hooks.

## Sign-in

| Situation     | Frontend does                                                                                    |
| ------------- | ------------------------------------------------------------------------------------------------ |
| Production    | "Continue with Microsoft" → `window.location = '/api/auth/login?returnTo=/dashboard'`            |
| Local / tests | Persona picker → `GET /api/auth/dev/personas`, then `POST /api/auth/dev/login {employeeCode}`    |
| On load       | `GET /api/auth/me` → user, role, `permissions[]` (frontend catalogue keys). 401 → go to `/login` |
| Sign out      | `POST /api/auth/logout`                                                                          |
| SSO error     | backend redirects to `/login?error=sso_failed\|sso_expired\|no_access`                           |

Use `permissions[]` from `/me` to drive the frontend's `can()` checks instead of the persona table. The backend
enforces the same rules regardless.

## Requests

- Send `credentials: 'include'` (same origin makes this automatic).
- Errors: switch on `code` (e.g. `company.unknown_location`), show `message`, log `requestId` for support.
- 401 → redirect to sign-in. 403 → "no access" state. 409 → refresh and show the conflict.

## Migration order (per module)

1. Backend endpoints + e2e tests merged, OpenAPI exported.
2. Regenerate the client; replace the module's store/context reads with API queries.
3. Replace mutations; remove the localStorage keys for that module (`gsit.*`).
4. Delete the mock data for that module from `lib/data.ts`.
